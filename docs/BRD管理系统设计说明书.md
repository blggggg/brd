# BRD 管理系统设计说明书

版本 1.1  
日期 2026 年 9 月 26 日  
阶段 第一期最小可用版本设计

## 1 目标与范围

本期只实现账号功能及 BRD 文件上传与版本管理。用户继续在 Word 等现有工具中编写文件，系统负责保管文件、串联版本、标记当前使用版本，并记录上传人和修改说明。

核心问题是同一份 BRD 出现“最终版”“最终确认版”等多个文件后，用户难以判断应使用哪一份。系统以稳定的文档编号组织文件，每次上传产生不可覆盖的版本，列表默认突出当前使用版本。最新上传的文件不自动等于当前使用版本。

本版替代 1.0 的第一期范围。审批、评审、会签、发布流程、变更申请、在线编辑、逐段内容对比、Git 分支合并均不在本期实施。此前含“审批通过”“发布 V7”的 UI 仅为旧方案，不作为当前验收依据。

### 1.1 本期功能

| 模块 | 必须实现 | 暂不实现 |
|---|---|---|
| 账号 | 管理员创建账号、登录、退出、修改密码、管理员重置密码、停用、角色配置 | 自助注册、短信登录、SSO、多租户 |
| 文档 | 新建文档记录、上传首版、上传后续版本、原文件下载 | 在线编辑、模板编辑、在线预览及文件格式转换 |
| 版本 | 自动版本号、上传记录、修改说明、当前使用版本、历史查询、相同文件提醒 | 逐段语义差异、多人分支、自动合并 |
| 查找 | 按文档编号、标题、项目名称、交付批次筛选 | 全文检索、智能问答 |
| 追溯 | 上传、下载、切换当前版、停用账号等操作日志 | 独立审计平台、审批证据、电子签名 |

第一期为同一团队的共享文档库，所有有效账号可读取全部已接收文档。不同部门间的机密隔离不在此模型中；若需要，应另行增加成员级授权，不能把本期共享库当作隔离空间。

### 1.2 Git 理念的轻量应用

保留四项：文档编号稳定、版本文件不可覆盖、每个版本有修改说明和上传人、当前版通过指针明确指定。界面不出现 commit、rebase、merge 等术语。

项目名称和交付批次作为文档记录的归属信息，例如“客户平台 / R1 维护”和“客户平台 / R2 开发”。每个文档记录仅对应一个交付批次，只有一个当前版本；不同批次需要独立文档编号。本期不实现跨批次分支同步。

## 2 账号与权限

采用管理员、上传者、阅读者三个角色；权限由服务器检查，不依赖按钮是否可见。

| 能力 | 管理员 | 上传者 | 阅读者 |
|---|---|---|---|
| 查看列表、历史、修改说明和下载 | 可以 | 可以 | 可以 |
| 创建文档并上传首版 | 可以 | 可以 | 不可以 |
| 上传后续版本 | 任意文档 | 本人负责的文档 | 不可以 |
| 指定或切换当前使用版本 | 任意文档 | 本人负责的文档 | 不可以 |
| 修改标题、项目名称和批次 | 任意文档 | 本人负责的文档 | 不可以 |
| 转交文档负责人 | 可以 | 不可以 | 不可以 |
| 创建账号、改角色、重置及停用 | 可以 | 不可以 | 不可以 |
| 修改本人密码、退出 | 可以 | 可以 | 可以 |

账号字段为用户名、显示名、角色、启用状态和创建时间。用户名唯一且不能复用已停用账号的名称；显示名可修改，历史操作始终保留账号 ID。账号不物理删除，以免破坏上传记录。

初始管理员在部署阶段一次性创建，不设置公开默认密码。管理员为新账号设置临时密码，用户首次登录必须修改。重置后同样强制修改，并撤销该用户既有会话；停用或角色变更后撤销既有会话并阻止旧权限继续使用。禁止停用最后一个有效管理员。

密码建议最少 12 位、允许密码管理器生成的长密码；服务端以密码编码器散列保存。接口、日志及前端都不提供“查看原密码”。登录失败提示不区分账号不存在与密码错误，实施按账号和来源的速率限制。

## 3 文档与版本规则

### 3.1 文档记录

同一文档的多次上传必须进入同一文档记录，不按文件名自动合并。文档包含系统编号、标题、项目名称、交付批次、负责人、当前版本、最新上传版本和最后更新时间。

编号示例为 BRD-000123，由服务器生成。文件名只作为原始名称保留，不作为身份或排序依据。创建表单遇到相同项目、批次和标题时显示可能重复的记录，用户可以打开已有文档继续上传，或明确选择创建独立文档；不自动合并内容。

文档创建和首版接收是一个业务操作：文件校验通过且元数据事务成功后，文档及 V1 才对外可见。失败时保留上传失败记录，但不留下可见的空文档。

### 3.2 上传规则

第一期仅接受 PDF 和 DOCX，每次上传一个主文件，单文件最大 20 MB。暂不接受 DOC、DOCM、ZIP、XLSX 或多个附件；不解析正文，不执行宏，不把 DOCX 容器当作可执行内容。

服务端检查大小、扩展名、声明 MIME、文件签名和基本结构。DOCX 必须为合法 OOXML 文档包，并限制解压检查资源；校验扫描失败、扫描服务不可用时不接收为可下载版本。扫描属于文件安全检测，不是业务审批。

每次上传填写修改说明，2 至 500 字，例如“将登录超时从 30 分钟改为 15 分钟”。上传人和时间由服务器记录，不允许用户伪造。服务器计算原始字节的 SHA-256，用于完整性校验和重复提醒；摘要不能代替业务修改说明。

同一文档内出现相同 SHA-256 时不新增版本，返回已存在版本并提示“文件内容与 Vn 相同”。不同文档间允许相同文件，不跨文档泄露重复结果。文件名不同但内容相同仍属于重复上传；内容不同但名称相同则生成新版本。

### 3.3 版本号及不可变文件

接收成功时按文档分配 V1、V2、V3 等递增序号，用户不能手工修改。每个版本另有内部唯一 ID、原文件名、存储键、摘要、大小、上传人、上传时间和修改说明。

已接收版本的原始文件、版本号、上传信息和修改说明不可覆盖。传错文件时上传修正版；版本管理不是在旧对象上替换内容。第一期不提供版本物理删除、文档物理删除、覆盖上传或强制重写历史接口。

### 3.4 当前使用版本

首个成功接收的 V1 自动成为当前使用版本。后续上传默认只新增版本，不自动替换当前版。上传成功页提供独立按钮“设为当前使用版本”，由负责人或管理员确认后切换；不需要审批人或审批流程。

切换弹窗显示原版本、目标版本、目标修改说明，并要求填写切换理由。指针可从 V5 切回 V3，称为“切换当前版本”，不会删除 V4、V5，不会让最大版本号倒退。两个用户同时切换时采用乐观锁，只接受基于最新文档 revision 的请求。

“当前使用”表示团队指定的文件，不表示已审批或业务验收。列表和详情必须分别展示当前版及最新上传版；当两者不同，提示“V7 已上传，当前仍使用 V4”。不得仅通过绿色或灰色区分状态，须有文字标识。

### 3.5 基于版本提示

上传后续版本时填写“基于哪个版本修改”，默认选当前版，允许选择同文档的历史版本。若选中的基于版本不是当前版，显示提示并允许用户确认继续。系统只记录用户声明的来源，不声称能自动判断 Word 文件究竟基于哪一版。

该字段用于追溯，不引入分支、冲突解决或合并。不同上传者提交的文件均独立保留；人工下载比较后再上传合并后的文件。

## 4 核心页面

左侧菜单只保留“文档库”和管理员可见的“账号管理”；右上角提供个人资料、修改密码和退出。不展示审批中心、待办、模板、发布或变更申请菜单。

| 页面 | 展示内容 | 主要操作 |
|---|---|---|
| 登录 | 用户名、密码、失败提示 | 登录；首次使用转修改密码 |
| 文档库 | 文档编号、标题、项目和批次、负责人、当前版、最新上传版 | 新建并上传、筛选、打开详情 |
| 文档详情 | 当前版突出展示、当前文件修改说明、完整版本列表 | 下载当前版、上传新版本、切换当前版 |
| 上传弹窗 | 文件、所属文档、基于版本、修改说明、大小限制 | 上传进度、取消、失败重试 |
| 版本详情 | 版本号、原文件名、上传者、时间、基于版本和说明 | 下载该版本；提示其是否当前版 |
| 账号管理 | 用户名、显示名、角色、状态 | 创建、改角色、重置密码、停用及启用 |

当前版始终置顶；历史列表按系统版本序号倒序，默认显示最近 10 条，支持分页。历史版下载前明确显示“不是当前使用版本”，但不阻止有读取权限的人获取历史文件。

下载名称包含文档编号、版本号和安全处理后的标题，例如 BRD-000123_V4_客户登录.docx。保留上传时的原文件名作为元数据，不以“最终版”推断状态。文件内容保持原样，不向原文件偷偷添加水印或标题。

页面提供稳定文档入口 /brds/{id}，打开后突出当前版；具体版本入口 /brds/{id}/versions/{versionId} 固定指向历史快照。两个入口均要求登录，不提供匿名公开链接。固定链接不自动跳到新版，以免丢失追溯上下文。

## 5 上传流程与一致性

### 5.1 用户主流程

管理员创建账号 → 用户登录及修改初始密码 → 创建 BRD 并上传 V1 → 下载当前版 → 上传 V2 并填写修改说明 → 负责人按需要设 V2 为当前 → V1 继续保留。

### 5.2 技术处理

上传任务状态为 RECEIVING、CHECKING、SUCCEEDED、FAILED、DUPLICATE、CANCELLED。前端依据真实传输进度展示上传进度，检查阶段显示“文件检查中”，不能提前显示版本创建成功。

文件先写入私有临时目录，校验扫描通过后以随机对象键完成持久化。随后数据库事务锁定文档记录，重新检查账号权限和文档归属、重复摘要，分配序号并插入版本、操作日志，更新最新版本指针；仅首版同时设置当前指针。

持久文件写入失败不得提交版本元数据。文件已经落盘而数据库失败时可能产生孤立对象，由清理任务在安全保留期后删除；任何有已接收版本引用的对象都不能清理。检查期间超时、网络断开和扫描失败都不能改变当前版。

上传使用客户端生成的 request_key，在同一用户内唯一，并绑定目标文档及请求摘要。相同请求重试返回原任务状态；复用键但内容不同返回 409。并发上传不同文件分配不同序号；相同文件由文档与摘要唯一约束去重。

用户停用、角色降级或文档转交发生在上传期间时，最终接收事务重新鉴权。取消只允许成功提交前；取消和最终提交竞争同一任务状态，只有一个结果生效。失败重试需要新 request_key，网络响应丢失则用原键查询，不能盲目重复建版本。

### 5.3 当前版切换

请求必须携带 expectedRevision。事务锁定文档、验证操作者、目标版本归属和已接收状态；revision 不匹配返回 409。成功时只更新 current_version_id、revision 和变更时间，追加一条包含前后版本及理由的操作记录。若目标已经为当前版，返回当前结果，不重复记切换事件。

## 6 数据模型

| 表 | 核心字段 | 约束 |
|---|---|---|
| app_user | id、username、display_name、password_hash、role、status、must_change_password、auth_version、created_at | username 唯一；角色为 ADMIN、UPLOADER、READER |
| brd_document | id、code、title、project_name、delivery_batch、owner_id、current_version_id、latest_version_id、next_sequence、revision、created_at、updated_at | code 唯一；当前和最新指针必须属于自身文档 |
| brd_version | id、document_id、sequence_no、base_version_id、object_key、original_filename、extension、sha256、size_bytes、change_note、uploaded_by、uploaded_at | document_id 与 sequence_no 唯一；document_id 与 sha256 唯一；object_key 唯一 |
| upload_job | id、actor_id、request_key、request_hash、document_id、create_metadata_json、base_version_id、change_note、temp_key、state、error_code、result_version_id、created_at、expires_at | actor_id 与 request_key 唯一；创建文档时 document_id 可先为空 |
| operation_log | id、actor_id、action、document_id、version_id、from_version_id、to_version_id、reason、request_id、created_at | 应用只追加；按对象时间索引 |

会话使用 Spring Session JDBC 管理的标准表，不新增审批、评审、评论、需求条目、变更申请、通知 outbox 或导出任务表。

版本是否为当前版由 brd_document.current_version_id 计算，不在每一条版本记录上另存 is_current，避免出现两个当前版。最新上传版本指向最大已接收序号，与当前指针独立。

ID 使用 BIGINT，API 中以字符串返回；时间统一存 UTC，界面按本地时区显示。base_version_id 可以为空（首版或用户明确选择来源未知），否则必须引用同文档较早版本。数据库外键及服务层共同保证引用完整性；账号停用后版本仍保留原上传者 ID。

## 7 接口设计

前缀 /api/v1，除登录和受限初始改密流程外均要求有效会话。分页默认 20 条，上限 100；过滤和排序字段使用白名单。

| 方法及路径 | 用途 | 关键校验 |
|---|---|---|
| POST /auth/login | 登录 | 账号启用、密码校验、限流 |
| POST /auth/logout | 退出 | 会话失效 |
| GET /auth/me | 当前账号信息 | 不返回密码散列 |
| PUT /auth/password | 修改本人密码 | 验证旧密码；撤销旧会话，要求重新登录 |
| GET /users | 账号列表 | 管理员 |
| POST /users | 创建账号 | 管理员；唯一用户名及临时密码 |
| PATCH /users/{id} | 修改角色、显示名、启用状态 | 管理员；保护最后一个有效管理员 |
| POST /users/{id}/password-reset | 设置临时密码 | 管理员；强制下次改密、撤销会话 |
| GET /brds | 文档列表 | 登录、分页和筛选 |
| POST /brd-uploads | 新文档与首版上传 | 上传权限；multipart 文件及元数据；幂等键 |
| GET /brds/{id} | 文档概览 | 返回当前与最新版本及 revision |
| PATCH /brds/{id} | 改标题、项目、批次及负责人 | 负责人或管理员；负责人转交仅管理员 |
| POST /brds/{id}/uploads | 后续版本上传 | 所有者权限、基于版本、修改说明、幂等键 |
| GET /uploads/{id} | 上传状态 | 仅本人或管理员 |
| POST /uploads/{id}/cancel | 取消未完成上传 | 本人或管理员；状态并发控制 |
| GET /brds/{id}/versions | 版本历史 | 按序号分页 |
| GET /brds/{id}/versions/{versionId} | 版本详情 | 版本归属匹配 |
| GET /brds/{id}/versions/{versionId}/download | 下载原文件 | 每次请求鉴权；安全文件名 |
| GET /brds/{id}/current/download | 下载当前版 | 请求开始时解析并锁定本次下载版本；响应带版本 ID |
| PUT /brds/{id}/current-version | 切换当前版 | 负责人或管理员、目标归属、expectedRevision、理由 |
| GET /brds/{id}/operations | 文档操作记录 | 登录；仅返回该文档的非敏感记录 |

上传接口接收文件后返回 202 和 uploadId，后续轮询任务。检查失败返回任务 FAILED 和稳定错误码；重复文件返回 DUPLICATE 和 existingVersionId，不新增版本。首次上传成功返回 documentId 和 versionId。

切换示例：PUT /api/v1/brds/123/current-version，正文 {"versionId":"456","expectedRevision":8,"reason":"本周开发按 V4 执行"}。成功返回最新文档 revision 和 currentVersionId；并发冲突返回 409 和最新 revision，让用户重新确认。

统一错误码包括 INVALID_CREDENTIALS、ACCOUNT_DISABLED、FORBIDDEN、FILE_TOO_LARGE、UNSUPPORTED_FILE_TYPE、FILE_CHECK_FAILED、DUPLICATE_FILE、VERSION_CONFLICT、UPLOAD_CANCELLED。HTTP 使用 401 未登录、403 无操作权限、404 不存在或资源不可访问、409 冲突、413 过大、415 类型错误、422 内容校验失败、429 限流。响应不回显密码、内部路径或数据库异常堆栈。

## 8 技术与安全

采用 Java 21、Spring Boot、Spring Security、Vue 3、TypeScript 和 MySQL 的单体应用。沿用已选技术方向，具体框架补丁在编码前锁定。后端仅分 identity、document、upload、storage、operation 五个业务模块，不引入流程引擎或富文本编辑器。

第一期采用单应用实例及挂载到持久卷的私有文件目录，路径在 Web 根目录之外。数据库仅保存元数据，下载经应用鉴权并流式返回。StorageService 抽象保留未来切换 S3 兼容存储的能力，但本期不同时实现两套后端。

上传目录、临时目录和文件安全检查组件独立配置。限制请求体、用户上传速率、账号存储额度和磁盘余量，检测到空间不足时拒绝新上传；临时文件清理不触碰历史文件。文件名仅用于展示及下载头，不参与服务器路径拼接。

会话 Cookie 设置 HttpOnly、Secure、SameSite=Lax，写接口启用 CSRF 防护，登录后更新会话 ID。账号停用和角色修改时废弃旧会话，服务端还需核对账号状态及 auth_version，不能只依靠客户端退出。

文档标题、修改说明和文件名作为纯文本转义展示，禁止直接插入 HTML。下载使用 attachment，设置 nosniff，不在同源页面内执行上传内容。日志不记录密码、Cookie、完整文件内容或服务器真实文件路径。

## 9 部署与备份

使用独立数据库 brd_management 及独立应用账号，不能复用 pet_db 或既有 root 凭据。账号功能的初始管理员密码和数据库密码均由运行环境提供，不放入 Git 仓库。

数据表由部署阶段的 Flyway 迁移创建；生产应用不执行自动建表。最小部署为 Linux 上一个应用实例、MySQL、文件持久卷、HTTPS 反向代理及文件检查组件。文件持久卷不能使用容器临时文件系统。

备份必须同时覆盖数据库和已接收文件。第一期每日备份，初始目标 RPO 不超过 24 小时、RTO 不超过 4 小时，以恢复演练为准。备份时暂停新增上传接收及当前版切换，或采用经验证的一致性快照方案；恢复后按数据库清单核对文件存在和 SHA-256。

监控磁盘剩余、上传失败率、文件检查积压、登录失败、数据库连接和备份结果。未被版本引用的临时及孤立文件按保留期清理，历史版本不自动删除。

## 10 验收标准

初始测试规模为 50 个账号、10 个并发活跃用户、1,000 份文档和 10,000 个版本元数据。列表和详情 P95 目标小于 1 秒；文件上传耗时单独记录传输和检查时间，不将网络速度归因于列表性能。目标需在明确硬件环境下验证。

| 编号 | 场景 | 通过条件 |
|---|---|---|
| AT01 | 新账号首次登录 | 必须修改临时密码后才可访问文档库 |
| AT02 | 停用账号和修改角色 | 旧会话失效；旧权限不能继续上传或下载 |
| AT03 | 阅读者越权 | 无法通过接口创建、上传或切换当前版 |
| AT04 | 首版上传 | 创建文档及 V1，V1 自动为当前版 |
| AT05 | 上传后续版本 | 生成 V2，V1 保留，当前指针不自动切换 |
| AT06 | 人工切换当前版 | 无审批步骤；记录操作者、理由和前后版本 |
| AT07 | 切回旧版 | 当前版切回 V1，V2 及上传记录仍存在 |
| AT08 | 相同文件重复上传 | 提示已有版本，文件改名不绕过去重 |
| AT09 | 上传失败或检查失败 | 不新增可见版本，不改变当前版 |
| AT10 | 并发和网络重试 | 不覆盖旧文件，不重复分配序号，不重复接收相同请求 |
| AT11 | 并发切换当前版 | 陈旧 revision 返回 409，不静默覆盖 |
| AT12 | 旧版本下载 | 页面明确标识历史版本，文件名包含文档编号和版本号 |
| AT13 | 文件安全 | 超限、伪造类型、危险或检查失败文件不能下载 |
| AT14 | 版本来源 | 基于版本必须属于同一文档，选历史来源时有提示 |
| AT15 | 账号重置与最后管理员保护 | 重置后强制改密，无法停用最后一个管理员 |
| AT16 | 备份恢复 | 文件及元数据可恢复，摘要一致 |

测试覆盖权限、上传失败补偿、幂等、并发、文件完整性及恢复，不包含审批、通知、在线编辑或语义 Diff 验收。

## 11 实施计划与后续边界

按一名后端、一名前端并有测试协作，初步估算 2 至 3 周；这是范围估算，不是已承诺的交付日期。

第一阶段实现账号、权限和文档列表；第二阶段实现安全上传、下载、自动版本号及历史；第三阶段实现当前版切换、重复提醒、操作记录及联调验收。

后续可按真实需求增加在线预览、文本差异、项目成员隔离、分支合并或审批。本期不预建这些业务表，不展示空菜单，不将流程功能列为上线依赖。
